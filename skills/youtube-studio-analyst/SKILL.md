# YouTube Studio 에이전트와 성과 검토

Studio 에이전트에 실제 채널 자료를 묻고, 핵심 수치·집계 범위는 Analytics 화면과 대조한다. 산출물은 **대화 기록, 확인/정정/미확인 판정, 다음 제작 실험**이다. 에이전트 답변을 원자료나 검증 완료 사실로 취급하지 않는다.

## 시작과 범위

- 환경의 `ego-browser` 스킬을 읽고 그 TaskSpace·페이지·사용자 제어 규칙을 따른다. 한 작업 공간 안에서 대화와 분석을 진행한다. 브라우저 연결 실패를 다른 브라우저나 세션으로 우회하지 않는다.
- 현재 사용자 요청과 기존 대화의 권한을 따른다. 이 스킬을 통해 Studio 에이전트와 성과를 검토하라는 요청은 해당 질문 전송을 포함한다. 단순 수치 열람에 불필요한 대화를 추가하지 않는다.
- 채널명·채널 ID를 화면에서 확인한다. 영상은 제목뿐 아니라 YouTube ID와 결과 폴더로 식별한다. 특정 채널 ID를 스킬에 고정하지 않는다.
- 성과 검토는 제목 수정·예약 변경·공개·댓글 게시를 포함하지 않는다. 별도 요청된 변경만 그 범위에서 수행한다.
- 저장소에 개선 관리 폴더가 있으면 README·현재 방향·최근 검토·측정 규칙을 먼저 읽는다. 이 작업 공간의 관례는 `workspace/stores/analytics/improvement/`, 편별 기록은 `workspace/stores/production/exports/`다. 다른 프로젝트에서는 기존 경로를 따른다.

## 실제 대화

Studio의 **YouTube 스튜디오에 물어보기 / Ask Studio**를 열고 채팅 입력에 질문한다. 기존 대화가 대상과 관련되면 이어가되, 이전 대화를 지우지 않는다. 기능이 없거나 사용할 수 없으면 그 상태를 기록하고 가능한 Analytics 조회를 수행한다. 실제 대화하지 못했는데 완료했다고 보고하지 않는다.

첫 질문은 이전 답의 숫자를 되풀이하기보다 채널·영상 ID와 필요한 지표를 지정한다. 필요한 범위에서 아래를 묻는다.

> 두 영상의 조회수, 참여/유효 조회수, 평균 시청 시간·조회율, 계속 시청함, 피드 유입, 구독 변화를 알려줘. 보고서 기간·필터·공개 후 경과 시간과 알 수 없는 항목을 구분해줘. 채널 합계와 영상 합계도 구분해줘.

후속 질문은 실제 발견한 불확실성에 맞춘다.

- “좋은 출발” 같은 평가에 어떤 비교군을 사용했는가? 유지율 그래프를 실제로 봤는가?
- 합계가 다르면 조회 기간·대상 영상·시간대가 같은가? 차이의 원인이 원자료로 확인됐는가, 추정인가?
- 계산·공식 지표 정의와 충돌하면 구체적 반례를 제시해 정정을 요청한다. 맞다고 강요하지 않고 근거·불확실성을 묻는다.
- 개선 제안에는 근거 지표와 미확인 원인, 실제로 바꿀 항목을 함께 요구한다.

답변 생성 중에는 중복 질문을 보내지 않는다. `보내기` 버튼 복귀만으로 완료를 판단하지 않는다. 실제 사용에서 버튼이 먼저 돌아오고 답변 본문이 나중에 나타났다. **새 답변 본문과 완료된 응답 제어**를 확인하고 다음 질문을 보낸다. 지연·오류 시 현재 대화에 질문이 들어갔는지부터 확인한다.

## 핵심 주장 대조

필요하면 같은 TaskSpace의 두 번째 페이지에서 Analytics를 열어 대화 문맥을 유지한다. 관찰한 링크와 현재 snapshot으로 이동하며 ref 번호는 재사용 가능한 상수가 아니다.

- 개요: 정확한 조회수, 구독 **순변동**, 게시 이후/선택 기간, 유지율 제공 여부.
- 참여도: 유효 조회수(Engaged views), 평균 시청 시간, 시청 시간, 계속 시청함. 화면의 지표명과 정밀도를 그대로 보존한다.
- 도달범위: Shorts 피드 유입 비중·필터. 유입 비중을 피드에서 계속 시청한 비율로 바꾸지 않는다.
- 정밀한 값이 필요할 때만 고급 모드/내보내기를 확인한다. `—`는 0으로, 반올림된 `1.3천`은 정확한 1,300으로 저장하지 않는다.

기간은 **화면에서 실제 선택된 범위**를 기록한다. 에이전트가 “첫 11시간으로 정규화”라고 말해도 화면이 게시 이후라면 동일 경과 시간 자료로 인증하지 않는다. 관측 시각과 서비스 데이터 마감 시각을 구분하고, 에이전트만 알려준 정확한 공개 시각은 출처를 표시한다.

평균 조회율 100% 초과는 전체 시청자의 완주율이나 반복 시청자 수가 아니다. Shorts 평균 시청 시간·조회율은 참여 조회수와 대응 시청 시간 기준이므로 총 조회수로 나눠 역산하지 않는다. 현재 정의가 필요하거나 충돌하면 [YouTube 공식 지표 설명](https://support.google.com/youtube/answer/12220281)을 확인한다. 보고서 범위가 다른 수치를 억지로 일치시키지 않는다.

Studio 에이전트가 오류를 인정해도 새 설명까지 자동으로 사실이 되지는 않는다. 화면·내보내기로 확인된 값, 에이전트 진술, 자체 해석을 구분한다. 유지율 곡선이 처리 중이면 문장별 이탈 원인과 영상 내용의 효과를 확정하지 않는다.

## 기록과 다음 제작 연결

- 대화 질문·응답 전체를 필요한 범위로 저장한다. 축약된 snapshot만 복사하지 말고 실제 렌더된 본문을 읽는다. URL·채널/영상 ID·관측 시각을 함께 남기며 비공개 데이터나 계정 인증 정보를 로그에 불필요하게 넣지 않는다.
- DOM 추출은 그 페이지에서 구조를 관찰한 뒤 사용한다. 2026-09 검증에서는 응답 본문이 `ytcp-ask-studio-item-view-model`에 있었지만 고정 인터페이스로 가정하지 않는다. DOM의 숨은 앱 상태·토큰에 의존하지 않는다.
- `reviews/날짜-studio-agent-check.md`에 기존 주장, 직접 확인 결과, 정정, 남은 한계를 적는다. `metrics/evidence/`에 대화·분석 화면의 원자료를 연결한다.
- 관측 CSV에는 확인된 수치를 출처별로 추가한다. `studio_ui`, `studio_export`, `studio_agent`를 구분한다. 다른 화면에서 얻은 값을 같은 시각의 단일 스냅샷으로 꾸미지 않는다. 과거 행을 지우지 말고 정정과 새 시점 관측을 구분한다.
- `DIRECTIONS.md`와 관련 실험의 근거를 갱신한다. 가설 등록을 실제 적용·효과 확인으로 바꾸지 않는다. 원자료 부족 시 우선순위는 잠정으로 유지한다.

결과는 **어떤 수치가 맞았는지, 어떤 설명을 정정했는지, 다음에 무엇을 시험할지**로 보고한다. 사용한 이 스킬과 검토 기록을 링크한다. ego-browser의 완료 절차로 작업 공간을 정리하고, 이어서 사용자가 볼 필요가 있는 결과 페이지만 예외적으로 남긴다.
